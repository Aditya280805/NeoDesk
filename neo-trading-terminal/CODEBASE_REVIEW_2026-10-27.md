# Codebase review and cleanup — 27 October 2026

## Verified fixes

- Stop/resume orders works without a missing request-body error. Risk controls and settings belong to the signed-in account, are applied to its manual live orders, and persist across restarts. Invalid negative/non-finite risk limits are rejected. CORS now permits the risk-settings PUT request.
- Paper order retry IDs are scoped to their account for stocks and futures. The database migration preserves legacy orders while replacing the global retry-ID constraint. Resetting paper trading also clears its old price-source binding.
- Backtests and strategy history use the owner's market session. Restored watchlists use the correct owner.
- Removed the unsupported automated live-order path that referenced a nonexistent broker client and bypassed the manual order workflow. Live algorithm deployment is rejected. There is no strategy market-feed producer in the running server, so saved strategies remain paused, including after restart, and can still be stopped. Historical backtesting and reviewed manual orders remain available.
- Normal development use now requires sign-in for private HTTP APIs. Invalid WebSocket tokens cannot fall back to the default account. The anonymous compatibility path is limited to explicitly configured tests; existing shared-password compatibility routes remain because they have documented/tested consumers.
- Frontend API requests use the HttpOnly session cookie. A stale browser-storage token no longer overrides it. Old WebSocket close/message callbacks cannot corrupt a replacement connection.
- Removed the unreachable live-risk panel and its unnecessary five-second poll from the paper-only screen, plus the order ticket's no-op live-price variable.
- Test fixtures no longer import the real application/database for live-execution tests. Test configuration explicitly avoids loading local credentials where corrected.

## Removed code and dependencies

- `backend/refactor.py`: obsolete one-off script containing older route implementations that could overwrite newer account-aware routes.
- `backend/app/config.py`: unused configuration re-export; application imports use `app.core.config`.
- Duplicate request models and unused imports left in `server.py` after routes moved into modules.
- Axios: no application references; API calls already use fetch.

No portfolio records or account files were deleted. The removed untracked helper files do not have a Git restore point; their deletion was limited to the confirmed unused helpers. A SQLite-consistent backup of the current database was created before relaunch at `data/backups/terminal-before-relaunch-20261027-26653d.sqlite3`. The legacy retry-key migration is covered by a row-preservation/reopen test.

## Dependency and build checks

Next.js and its lint configuration were updated to 16.4.1. The official [16.4.1 release](https://github.com/vercel/next.js/releases/tag/v16.4.1) contains the security fixes identified in the installed version. The affected selector parser and Zod dependencies were updated within their permitted dependency ranges. The lockfile was regenerated by npm.

Windows Application Control blocks the new native SWC binary on this machine. The project now uses Next's supported Webpack build/dev option and its WebAssembly compiler fallback. No Windows security policy was changed. The app is served as a static frontend export alongside FastAPI.

## Remaining limitations

- Real Kotak holdings/positions retrieval still requires a fresh user login. The earlier upstream positions rejection has not been reproduced against the user's real session; simulated broker tests do not prove that account permissions or upstream availability are resolved. No real trades were submitted during this review.
- Automatic strategy execution is intentionally unavailable. A per-account market feed, durable strategy cost basis and fill reconciliation must be completed before it can be enabled. Existing saved strategies and positions are retained.
- Daily-loss accounting is not connected to actual broker fills. The order value/quantity/price limits and stop switch are tested, but a configured daily-loss threshold should not be treated as a verified live protection.
- A full production security assessment, broker integration acceptance test, Render deployment and end-to-end real order testing remain separate work. This review covers the active application, its routes, frontend, tests and dependencies; reference SDK checkout and generated build files were not treated as application source to delete.
- The earlier optional saved-connection/passkey/QR-login discussion has not been implemented by this cleanup.
